# BRMedia M9 analysis architecture

## Generation

Persistent BRMedia analysis generated by M9 is identified by
`brmedia-analysis-m9-v1`. Missing or different identifiers are not current M9
results. The underlying deterministic B1-B12 stages retain their individual
format and implementation fingerprints.

## Authority boundaries

| Field family | Authority |
| --- | --- |
| Live transport, position, beat phase, live BPM, sync, quantize, mixer and meters | Mixxx live authoritative while Mixxx Backend is active |
| Base/precise analysed BPM, stored grid, downbeat, tempo classification/segments, drift validation and confidence | BRMedia stored authoritative |
| Waveform peaks, spectral bands, transient/detail data and prepared state | BRMedia stored authoritative |
| Musical key | BRMedia stored authoritative when a verified analyser exists; unavailable in M9 v1 and marked Review Required |
| Title/artist shown on a live Mixxx deck | Mirrored display value; never imported into the BRMedia catalogue |
| Mixxx library/database analysis | Explicit future import/export candidate only; M9 never reads or writes Mixxx SQLite |

Mixxx live state is never persisted as BRMedia analysis. BRMedia analysis never
overwrites live Mixxx timing.

## Queue and recovery

Queue state is atomically persisted in `server/data/dj-analysis-queue.json`.
Concurrency is fixed at one track. Completed and Review Required items remain
complete across restart. An interrupted `analysing` or `preparing-waveform`
item is returned to `queued`; pending order is retained. A queue that was
running resumes after restart, while a paused queue remains paused.

Duplicate active requests are rejected. Current-version prepared tracks are
skipped unless force reanalysis is explicit. Pause takes effect between tracks;
the active decoder is allowed to finish safely. Cancel changes pending entries
only and does not kill an active FFmpeg process.

## Output safety

Original audio is opened read-only. Cache JSON uses atomic temporary-file
replacement and is parsed and compatibility-validated before a track is marked
prepared. A failed job removes its derived waveform cache, leaving stored
analysis from other tracks intact. No embedded tags, artwork, recordings,
analysis history, or Mixxx database records are modified.

The full-catalogue enqueue endpoint requires the exact explicit production
approval marker `M9_FULL_CATALOGUE_APPROVED`.
